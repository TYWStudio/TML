# 扩展安全边界（TML Extension API v1）

本文是 [README.md](README.md) 第 5、6、10 节的展开说明。数值与名称以 README / `schema/manifest.schema.json` 为准。
扩展是**不可信输入**，所有约束由宿主强制，不依赖扩展自觉，也不依赖 SDK。

## 1. 默认拒绝

- 扫描到的扩展一律 `Disabled`，`Scan()` 只解析清单、算 SHA-256，不启动进程、不执行入口。
- 用户必须看到「名称 / 作者 / 版本 / 声明的权限列表 / 包 SHA-256」后显式确认；
  `Enable(id, userConfirmed:=False)` 一律拒绝，代码里没有任何「开发者模式 / 高级权限 / 信任后放开」的后门。
- 指纹写入 `trusted.json`；包内容一变，自动禁用并要求重新确认，防止「确认过一次」后被替换。
- manifest 里出现**任何未知权限 / 未知事件 / 未知平台**，整个包拒绝加载，
  避免未来新增敏感能力时被旧宿主静默忽略。

## 2. 永不开放的能力

| 能力 | 风险 |
| --- | --- |
| 任意文件读写 / 目录遍历 | 窃取 `.minecraft` 会话令牌、账户文件，篡改启动器 |
| 任意网络访问 | 数据外带、SSRF、把启动器变成代理节点 |
| 启动任意进程 / shell 命令 | 等价于任意代码执行，绕过全部限制 |
| 账户 / 令牌 / 正版登录态 | 账号盗用 |
| 设备码 / 内测码 / 更新码 / 服务端地址 / 通信密钥 | 身份冒用、越权下载、伪造上报 |
| 注册表 / 系统环境变量 / 剪贴板 / 提权 | 凭据窃取、持久化驻留 |
| 读写启动器全局设置 | 篡改服务端地址、更新通道、关闭安全上报 |
| 启动 / 停止游戏、触发更新、下载安装 | 注入启动参数、供应链攻击、假更新包 |
| 反射 / JNI / ClassLoader / dex 加载 / 宿主内部对象 | 拿到启动器进程内凭据 |
| 访问其它扩展数据 / 跨扩展通信 | 横向越权 |

宿主侧另有一份**硬编码方法黑名单**（`DeniedMethods` / `DENIED_METHODS`），
以及 `network.*`、`file.*`、`process.*` 前缀拦截，收到一律回 `-32001` 并记日志。
需要这些能力的功能应直接写进启动器本体走代码审查，而不是做成扩展。

## 3. 进程隔离

- 扩展永远是独立子进程：不 DLL 注入、不加载程序集 / jar / dex、不内嵌脚本引擎、不反射。
- 环境变量**先全部清空**，只重设最小白名单：`PATH` / `SystemRoot` / 临时目录 /
  `USERPROFILE`·`HOME` / `LANG`·`LC_ALL` / `PYTHONIOENCODING=utf-8`。
  显式不带：`NODE_OPTIONS`、`PYTHONPATH`、`PYTHONHOME`、`PYTHONSTARTUP`、
  `JAVA_TOOL_OPTIONS`、`_JAVA_OPTIONS`、`CLASSPATH`、`LD_PRELOAD`、
  `DYLD_INSERT_LIBRARIES`、`CDPATH`、`TYW_SERVER*` 以及任何启动器内部变量。
- 工作目录 = 该扩展的私有目录；私有目录、包名、entry 全部经过 `GetFullPath` / 规范化校验，
  拒绝 `..`、绝对路径、盘符、UNC、`\`、符号链接与 ZIP Slip。
- 启动命令用参数数组 / 固定命令拼装，不经过 `cmd /c` / `sh -c`，不做 shell 插值。
- 握手 10 s、单次请求 5 s、单行 64 KiB、单包 8 MiB / 64 文件 / 单文件 2 MiB，
  每扩展 1 个进程、宿主总进程 ≤ 8；超时 / 崩溃 / 协议错误自动结束进程并禁用，不自动重启。
- 找不到 `python3` / `node` / `java` 时显示「缺少运行时」并保持禁用，
  **宿主绝不自动下载或安装运行时**。

## 4. 受控能力的收紧

- 能力白名单只有 7 个：`log`、`toast`、`host.info`、`instances.list`、`events`、`storage`、`settings`。
  方法名到权限的映射在宿主侧判定，扩展发来的 `permissions` 字段不是授权凭证。
- `instances.list` 只回 id / 名称 / 游戏版本 / 加载器，不含路径、命令行、账号、token。
- `storage` 只接受 `[A-Za-z0-9._-]` 的 key，不接受路径参数，值 ≤ 64 KiB，
  落盘路径必须在私有目录内，写用临时文件 + 原子替换，单扩展总量 ≤ 1 MiB。
- `settings` 只能读写 `ext.<extId>.` 命名空间，值 ≤ 8 KiB，改不了任何启动器设置。
- 日志 ≤ 4 KiB、提示 ≤ 300 字且过滤控制字符；事件数据脱敏，
  丢弃路径、URL、堆栈、用户名以及任何含 token / secret / password 等敏感词的键值。
- `host.info` 只回平台 / 架构 / 版本 / 通道 / 语言 / API 版本，**不含**设备码、服务端地址、账户。

## 5. Android 特别说明

ART 不是 JVM，系统通常不带 Python / Node.js。Android 端因此：

- 不用 `DexClassLoader` / `PathClassLoader` / 反射，不加载 jar 里的 class，不 dex 化；
- 不引入脚本引擎，不执行应用私有目录下的二进制；
- 只探测系统 PATH 里已存在的解释器，默认找不到任何运行时 → 全部保持禁用。

这是有意为之的安全限制，不是功能缺失。

## 6. 已知限制（如实说明）

「接口不开放」≠「操作系统级沙箱」。桌面端的隔离是**进程级隔离 + 能力白名单**：
Python / Node / JVM 进程内部仍能调用各自标准库读写文件、联网，这是解释器自身能力，
宿主无法在四端用统一方式剥夺。因此**只启用你信任来源、并审阅过源码的扩展**；
宿主提供的是校验、确认、指纹与一键禁用，**不构成安全执行环境**。
需要强隔离时应自行配合系统沙箱（AppContainer / seccomp-bpf / sandbox-exec / SELinux）
或在容器 / 虚拟机中运行启动器。

## 7. 报告漏洞

发现越权路径请提 issue，附上扩展包、manifest、复现步骤、受影响平台；
不要公开尚未修复的漏洞细节。
